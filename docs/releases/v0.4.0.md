# PotPlayer FrameClip 0.4.0 预览版

这版集中更新界面、后台任务和菜单可靠性。仍从 PotPlayer 右键菜单操作，不增加独立操作浮层。

## 本次更新

- 设置、任务中心和提醒共用原生界面与浅色/深色主题。调整标题栏、保存反馈、字体对齐及高 DPI 布局。
- 默认两路视频并行，截图独立运行；采用播放优先资源策略。任务支持实际进度、取消、重试和历史记录。
- 提醒支持多屏、四角可视化选择和拖放自定义位置，跟随外观设置。
- GPU 优先处理默认开启，按 FFmpeg、显卡和源格式能力选择解码后端；不可用时回退 CPU，保留现有色彩与编辑编码链路。
- 修复所有插件菜单误开“关于 PotPlayer”的桥接初始化问题，增加目标进程确认和有间隔的恢复重试；继续放行播放器自身命令。
- 安装、升级、卸载界面统一，支持备份与失败回退；没有 FFmpeg 也可以先安装，之后再配置。
- 修复开发验证时测试界面短暂闪到当前屏幕的问题：最大化、菜单和提醒预览测试移到独立的非输入桌面，不切换用户桌面，也不进入安装包。

## 下载与升级

下载 `PotPlayerFrameClip-v0.4.0-Setup.exe`，并使用同名 `.sha256` 文件核对校验值。安装包未进行商业代码签名，请确认来源，不要关闭系统安全防护。

先等待截图/导出完成，再正常退出 PotPlayer 和 FrameClip，随后运行安装包。升级不是运行中热替换；原生桥接 DLL 必须在播放器完全退出后更换。默认保留设置、任务记录与导出素材。

公开轻量包不附带 FFmpeg。可选择已有 `ffmpeg.exe` / `ffprobe.exe`，或稍后配置；未配置时截图和导出不可用。含 FFmpeg 的 Full 包暂不公开上传，须先完成对应源码、构建配方及依赖许可归档。

## 已验证与限制

- 本机构建、单元回归、隔离安装/卸载及 x86/x64 原生桥接回归通过；菜单九项动作覆盖 100/150/200% 缩放。
- 实际 PotPlayer 菜单已验证设置和截图；这不等同于所有皮肤和显示器组合均通过。
- NVIDIA 主机已进行媒体/GPU 对照；Intel/AMD 目前有调度策略测试，尚不能视为实机验证。短任务可能比 CPU 更慢。
- 混合 DPI、多种皮肤及长时间使用仍需继续验收，因此本次标记为预览版。
- GPU 主要加速解码，并非所有滤镜与编码都在 GPU 上运行；ProRes/DNxHR 和 16-bit 图片不以牺牲输出格式换取速度。
- HDR 原图保留源传递函数；可选 Rec.709 SDR 副本不是可逆母版转换。Dolby Vision 动态元数据不会烘焙到图片或精确转码片段。

## English

0.4.0 is a preview release with a redesigned native interface, real export progress, two concurrent video jobs, an independent screenshot lane, configurable notification placement, GPU-preferred decoding and safer maintenance. It fixes bridge initialization that could send FrameClip menu actions to About PotPlayer.

Download the lightweight installer and its SHA-256 file. Wait for jobs to finish and close both PotPlayer and FrameClip before upgrading. The installer does not include FFmpeg; you may configure an existing FFmpeg/FFprobe pair or do so later. The Full offline package is withheld pending corresponding-source and dependency-license archival.

Local installation and automated x86/x64 regressions pass. NVIDIA media tests and live settings/capture checks were performed; Intel/AMD real-device coverage, broader skins, mixed-DPI and long-duration acceptance remain incomplete. GPU decoding does not mean end-to-end GPU rendering or guaranteed speedups.
